# 테스트

`qo-logic.js`(엑셀 처리 로직)만 검사한다. 화면(qo-app.js 등)은 브라우저가 필요해서 여기서 다루지 않는다.

## 돌리는 법

```bash
npm install     # 처음 한 번만 (exceljs 를 받는다)
npm test
```

`node_modules` 는 커밋하지 않는다(`.gitignore`). 앱 배포에는 아무 영향이 없다 —
GitHub Pages 는 `index.html` 과 `qo-*.js` 만 쓰고, `package.json`·`test/` 는 그냥 안 읽힌다.

## 왜 시간대를 고정하나

`npm test` 는 `TZ=Asia/Seoul` 로 돌린다. 엑셀 일련번호(46231 같은 숫자)를 날짜로 바꿀 때
시간대에 따라 날짜가 하루씩 밀릴 수 있어서, 실제 사용 환경과 같은 한국 시간으로 고정해 검사한다.

## 무엇을 지키고 있나

| 파일 | 내용 |
|---|---|
| `date.test.js` | 일련번호·문자열 → 진짜 날짜 변환, 날짜 열·날짜 서식 판별 |
| `fields.test.js` | 헤더 → 표준 항목 매핑. **'주문수집일자' 를 '주문일시' 가 채가지 않는 것** 포함 |
| `convert.test.js` | 발주서 변환. **날짜 서식이 수량·금액 칸으로 번지지 않는 것**(스타일 공유 오염) 포함 |
| `invoice.test.js` | 송장 취합. **송장번호 앞자리 0 이 사라지지 않는 것** 포함 |

★ 표시한 세 가지는 눈으로 확인하기 어렵고 한 번 터지면 업체에 잘못된 파일이 나가는 것들이라,
`qo-logic.js` 를 고칠 때마다 `npm test` 를 돌려보는 게 좋다.
